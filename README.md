# Vector KB

Справочник автошколы «Вектор» как HTTP-сервис. Голосовой агент спрашивает — сервис отдаёт факты о городах и филиалах, из которых агент строит реплику клиенту.

Внутри 41 город и 235 филиалов, собранных с сайта сети. Данные лежат в памяти процесса, поэтому ответ занимает микросекунды: сервис ставится на ту же машину, что и агент, и сетевых задержек между ними нет.

Помимо чтения сервис умеет обновлять данные сам — парсер сайта встроен и запускается ручкой.

---

## Быстрый старт

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
make run
```

Сервис поднимется на `http://127.0.0.1:8317`, Swagger — на `/docs`.

Проверка, что живой:

```bash
curl localhost:8317/api/health
```

```json
{"status":"ok","cities_count":41,"branches_count":235,"loaded_at":"2026-07-23T11:02:42.488554Z"}
```

В Docker:

```bash
cp infra/.env.example infra/.env
make run_local_project
```

## Как этим пользуется агент

Три шага за разговор.

**Первый — город, один раз за звонок.** Клиент говорит «я из Питера» — агент отправляет это в `/api/cities/resolve` и получает слаг. Если города в сети нет, приходит `slug: null`, и это валидный ответ «филиала здесь нет», а не ошибка.

Второй путь надёжнее: отдать модели `/api/cities/enum` как перечисление в описании инструмента. Тогда модель выбирает из готового списка, и пришедший обратно слаг существует по построению.

**Второй — мета города.** По слагу забирается всё, что бот может рассказать: сколько филиалов, какие категории и сроки, на каких машинах учат, какие форматы теории, что нужно принести, частые вопросы с ответами. Это кладётся в контекст один раз и живёт весь разговор.

**Третий — филиал, когда клиент назовёт район или улицу.** Список филиалов города отдаётся отдельно, слаг филиала уникален на всю сеть, по нему забирается адрес, часы работы, перерыв и ориентир.

## Эндпоинты

Все под префиксом `/api`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | живость, число городов и филиалов в памяти, время загрузки |
| `GET` | `/cities` | список городов: слаг, название, число филиалов |
| `GET` | `/cities/enum` | плоский список слагов — для enum инструмента модели |
| `GET` | `/cities/resolve?text=` | разговорное название → слаг или `null` |
| `GET` | `/cities/{city_slug}` | полная мета города |
| `GET` | `/cities/{city_slug}/branches` | филиалы города: слаг, адрес, ориентир |
| `GET` | `/cities/{city_slug}/branches/enum` | плоский список слагов филиалов |
| `GET` | `/branches/{branch_slug}` | полная мета филиала |
| `POST` | `/parse` | запуск обновления данных в фоне |
| `GET` | `/parse/{job_id}` | статус задачи парсинга |
| `POST` | `/reload` | перечитать файлы в память без перезапуска |

Неизвестный слаг даёт `404` с понятным текстом:

```json
{"detail": "Город «moskva» не найден"}
```

### Ключи ответов

Имена полей английские, человеческое название лежит в `title` — Swagger читается по-русски, а агент получает стабильные ключи. Значения остаются русским текстом справочника.

### Примеры

**Разбор города**

```bash

```

```json

```



## Обновление данных

Полный обход сайта занимает около десяти минут, поэтому синхронно он не отдаётся.

```bash
curl -X POST localhost:8317/api/parse \
  -H 'Content-Type: application/json' \
  -d '{"only": ["omsk", "krasnoyarsk"], "force": false, "include_external": false, "include_done": false}'
```

Ответ `202`:

```json
{"job_id": "a1b2c3d4e5f6", "status": "pending"}
```

Статус:

```bash
curl localhost:8317/api/parse/a1b2c3d4e5f6
```

Параллельно выполняется не больше одной задачи — повторный запрос получит `409` с идентификатором текущей.

### Параметры

**`only`** — обновить только перечисленные города. Остальные файлы справочника остаются нетронутыми. Это поведение защищено тестом: раньше частичный прогон стирал сорок городов из сорока одного.

**`force`** — перекачать страницы, игнорируя кэш в `data/raw`. Без него повторный прогон работает по сохранённым страницам и сайт не дёргает.

**`include_external`** — включить Липецк, Челябинск и Калининград. У них отдельные домены и другая вёрстка, за результат разбора там никто не отвечает.

**`include_done`** — по умолчанию выключен. Санкт-Петербург, Екатеринбург и Пермь собраны и выверены руками: там заполнены районы, примечания и расхождения, которых автоматический разбор не даёт. Включив флаг, вы перезапишете их выдачей парсера и потеряете эту работу.

### Что происходит после запуска

Пайплайн идёт по шагам: сбор страниц → заполнение разделов → финализация слагов и ориентиров → пересборка индекса → пересборка данных справочника → сброс кэша в памяти.

Перезапускать контейнер не нужно: по успешном завершении новые данные сами оказываются в памяти.

Если на любом шаге случится ошибка, задача помечается `failed`, а данные в памяти остаются прежними. Отдельно стоит страховка: если после прогона городов в справочнике стало меньше, чем было, задача падает с ошибкой вместо молчаливой потери данных.

Реестр задач живёт в памяти процесса — при перезапуске история запусков теряется. Для одного инстанса рядом с агентом этого достаточно.

## Почему в API нет цен

На сайте цена подаётся как «специальная цена от N рублей». Мы сверили её с независимыми источниками, и расхождение оказалось не косметическим.

По Екатеринбургу: сайт обещает от 24 950 ₽, каталог Drom указывает диапазон 38 000 — 47 000 ₽, а ученики в отзывах называют суммы 35 000, 45 000, 48 000, 56 900. Менеджер в записанном разговоре называет 35 900. Медиана реально уплаченного — около 47 тысяч, то есть почти вдвое выше витрины. В рекламном блоке 2ГИС по тому же городу висит третье число — 19 450 ₽.

Если бот назовёт цифру с сайта, клиент приедет в офис и услышит вдвое больше. Поэтому цена не отдаётся ни в каком виде: полей с ценой нет в схемах, а тест проверяет, что ни один ответ не содержит слова «цена» и символа `₽`.

Когда заказчик даст настоящий прайс, он вливается в те же файлы, а схемы дополняются отдельно.

## Что осталось незаполненным

Не из-за кода — этих данных нет на источнике.

**Расписание групп.** Ни в одном из 41 города на сайте нет конкретных дат старта и остатка мест — только формулировка «старт каждые 15 дней». При этом менеджеры в записанных разговорах оперируют датами постоянно. Живёт в CRM заказчика.

**Районы и метро.** Почти везде пустые. Сайт районы не пишет, а 2ГИС и Zoon, где они есть, закрыты для автоматического доступа. Из-за этого бот не поймёт «я в Академическом» и «мне удобнее на Уралмаше» — понадобится проставить руками по крупным городам.

**Ориентиры заполнены частично** — 43 филиала из 235. Взяты из выгрузки 2ГИС: «ТРК Нарва», «Гостиница Октябрьская», «Моби Дик», «ТЦ Балканский». В Петербурге закрыто 8 филиалов из 11, в Екатеринбурге — 1 из 20, потому что в исходной выгрузке для него ориентир всего один.

**Сроки обучения у трёх ручных городов.** У Санкт-Петербурга, Екатеринбурга и Перми карточки категорий заполнены в старом формате, поэтому `duration` и `start_frequency` приходят пустыми. Автоматически собранные города эти поля отдают.

### Данные

Каталоги, которые появляются при парсинге и не попадают в репозиторий:

```text
data/raw/<slug>.html    сырая страница (после разбора можно чистить: make clean_raw)
data/raw/<slug>.txt     плоский текст — для проверки спорных мест
data/out/<slug>.json    полный справочник со всеми полями
data/index.json         сводный индекс городов и филиалов
```

В репозитории лежит только урезанный справочник в `app/services/directory_service/data` — то, что сервис отдаёт наружу. Из него выброшены тарифы, акции, повышение цен, расхождения и служебные пометки.

## Терминальный поиск

Для проверки данных руками, без HTTP:

```bash
make lookup
```

```
слаг> perm
слаг> perm_chernyshevskogo
слаг> города
слаг> филиалы perm
слаг> выход
```

Слаг города и слаг филиала различаются автоматически. Обрезанный слаг подскажет похожие:

```
слаг> perm_chernysh
  Не нашёл. Похожие:
    perm_chernyshevskogo
```

Разовый запрос: `uv run vector-lookup perm_chernyshevskogo`.

## Docker

Образ на `python:3.11-slim`, зависимости ставятся через `uv sync --frozen`. Порт публикуется только на локальный интерфейс — наружу сервис не смотрит, аутентификации в нём нет по этой же причине.

Собранные данные лежат на именованных томах:

```yaml
volumes:
  - vector_kb_out:/app/data/out
  - vector_kb_directory:/app/app/services/directory_service/data
```

Без этого результат парсинга исчезал бы при перезапуске контейнера, и сервис откатывался бы на снимок из образа.

## Тесты

```bash
make test        # 91 тест, офлайн
make api_tests   # чёрный ящик по поднятому сервису
```

Сеть тесты не трогают: подменяется только функция загрузки страницы, всё остальное — разбор, финализация, сборка — работает на сохранённых фикстурах.

Отдельно покрыты два сценария, которые однажды ломали данные: частичный прогон не должен уменьшать число городов, а полный — не должен трогать города, собранные руками.

## Отступления от внутреннего стандарта

Два, оба осознанные.

**Пакетный менеджер `uv`** вместо `requirements.txt` и pip. Проект изначально на `uv`, `uv.lock` в репозитории, Dockerfile ставит зависимости через `uv sync --frozen`.

**Нет слоёв `models`, `crud` и Alembic.** Источник истины — JSON-файлы на диске, базы данных в проекте не будет. Добавлять SQLAlchemy, Redis или очереди под текущие задачи не нужно.
