# vector_kb — справочник

FastAPI поверх данных сайта сети автошкол. Мозг спрашивает — сервис отдаёт факты
о городах и филиалах: адреса, часы работы, категории, сроки, тарифы, частые
вопросы, координаты. Из этих фактов мозг строит реплику.

Инвариант жёсткий: **чего нет здесь — того бот не произносит**. Выдуманная цена
вернётся претензией при оформлении договора.

Внутри **41 город и 212 филиалов**. Данные лежат в памяти процесса, поэтому
ответ занимает микросекунды. Помимо чтения сервис умеет обновлять данные сам —
парсер сайта встроен и запускается ручкой.

---

## Место в связке

```
vector_voice_agent ──HTTP──▶ vector_kb ──▶ JSON-файлы в памяти
                                       └──▶ геокодер (DaData / Nominatim)
```

**Кто его зовёт.** Только мозг. Голосовой бот сюда не ходит.

**Кого зовёт он.** Внешний геокодер — при переводе произнесённого места в
координаты, и сайт сети — при запуске парсинга. В обычной работе не ходит никуда.

**Что будет, если не отвечает.** Бот перестанет называть цены, адреса и филиалы.
Симптом обманчивый: со стороны это выглядит как «модель начала выдумывать» или
«бот отказывается отвечать». Смотреть логи справочника, а не мозга.

Мозг обращается с коротким таймаутом и кеширует ответы, поэтому короткая
недоступность переживается: факта не будет, но шаг разговора не пропустится —
ход к человеку сделается без чисел.

---

## Как этим пользуется мозг

Четыре шага за разговор.

**Город — один раз за звонок.** Надёжный путь — отдать модели `/api/cities/enum`
как перечисление в описании инструмента: тогда пришедший обратно слаг существует
по построению. Быстрый путь на точное совпадение — `/api/cities/resolve`; если
города в сети нет, приходит пустой слаг, и это валидный ответ «филиала здесь
нет», а не ошибка.

**Мета города.** По слагу забирается всё, что бот может рассказать: филиалы,
категории и сроки, автопарк, форматы теории, документы, частые вопросы,
рассрочка, контакты, тарифы. Кладётся в контекст один раз и живёт весь разговор.

**Филиал — когда клиент назовёт район или улицу.** Слаг филиала уникален на всю
сеть; по нему забираются адрес, часы работы, перерыв, ориентир, тип точки и
статус.

**Ближайший филиал по месту.** Клиент называет район или ориентир → `/api/geocode`
с текстом и слагом города → координаты → `/api/branches/nearest`. В ответе —
учебные офисы с расстоянием по прямой. Автодромы и точки со статусом «скоро
открытие» в подбор не входят: на автодром за договором ехать не надо, а в
неоткрытый офис человека записывать нельзя.

## API

Всё под префиксом `/api`. Swagger — на `/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | живость, число городов и филиалов в памяти, время загрузки |
| `GET` | `/cities` | список городов |
| `GET` | `/cities/enum` | плоский список слагов — для перечисления в инструменте |
| `GET` | `/cities/resolve` | разговорное название → слаг или пусто |
| `GET` | `/cities/{city_slug}` | полная мета города |
| `GET` | `/cities/{city_slug}/branches` | филиалы города |
| `GET` | `/cities/{city_slug}/branches/enum` | плоский список слагов филиалов |
| `GET` | `/geocode` | место словами → координаты |
| `GET` | `/branches/nearest` | ближайшие филиалы к точке |
| `GET` | `/branches/{branch_slug}` | полная мета филиала |
| `POST` | `/parse` | запуск обновления данных в фоне |
| `GET` | `/parse/{job_id}` | статус задачи парсинга |
| `POST` | `/reload` | перечитать файлы в память без перезапуска процесса |

Неизвестный слаг даёт 404 с понятным текстом. Ненайденное место в `/geocode` —
не ошибка, а признак «не нашлось». Пустой результат `/branches/nearest` — пустой
список и код 200.

Имена полей английские, человеческое название лежит в `title`: Swagger читается
по-русски, а мозг получает стабильные ключи.

## Локальный запуск

Нужен `uv`.

```bash
uv sync
cp .env.example .env
make run          # uvicorn на :8317 с автоперезагрузкой
make ok           # проверка живости
```

В docker:

```bash
cp infra/.env.example infra/.env
make run_local_project
```

Порт 8317 выбран намеренно: восьмитысячный на рабочей машине занят.

**Как убедиться, что работает.** `/api/health` должен вернуть 41 город и 212
филиалов. Если числа нулевые — справочник не прочитался с диска, смотреть
`DIRECTORY_DATA_DIR`.

Для проверки данных руками, без HTTP, есть терминальный поиск: `make lookup`.
Слаг города и слаг филиала различаются автоматически, обрезанный слаг подскажет
похожие.

## Обновление данных

Полный обход сайта занимает около десяти минут, поэтому синхронно не отдаётся:
`POST /api/parse` возвращает идентификатор задачи, статус читается отдельно.
Параллельно выполняется не больше одной задачи.

Четыре параметра, и три из них — предохранители:

- **`only`** — обновить только перечисленные города; остальные файлы не
  трогаются. Раньше частичный прогон стирал сорок городов из сорока одного,
  теперь это защищено тестом.
- **`force`** — перекачать страницы, игнорируя кэш сырых страниц.
- **`include_external`** — включить города на отдельных доменах (Липецк,
  Челябинск, Калининград). Другая вёрстка, за качество разбора там никто не
  отвечает.
- **`include_done`** — Санкт-Петербург, Екатеринбург и Пермь собраны и выверены
  руками. Включив флаг, вы перезапишете их выдачей парсера и потеряете эту
  работу.

Пайплайн: сбор страниц → заполнение разделов → финализация слагов и ориентиров →
пересборка индекса → пересборка данных справочника → сброс кеша в памяти.
Перезапускать контейнер не нужно. Ошибка на любом шаге помечает задачу
неуспешной, данные в памяти остаются прежними. Отдельная страховка: если после
прогона городов стало меньше, чем было, задача падает вместо молчаливой потери
данных.

Реестр задач живёт в памяти процесса — при перезапуске история теряется.

### Координаты

После добавления или правки филиалов координаты проставляются скриптом
`scripts/geocode_branches.py`: он обходит JSON городов, для каждого филиала без
координат спрашивает геокодер и пишет точку обратно. Центр города заполняется
тем же прогоном. Аргументы: один город, сухой прогон, пересчёт уже заполненных,
выбор провайдера.

Полный адрес в справочнике скрипт не меняет: если в нём оказались этаж или
офис, они срезаются только в запросе координат — это страховка, а не способ
заполнения. Правила записи адреса — в `docs/ADDRESS_RULES.md`.

## Переменные окружения

Только имена и назначение.

| Имя | Назначение |
|---|---|
| `APP_TITLE`, `APP_VERSION` | заголовок и версия в Swagger |
| `API_HOST`, `API_PORT` | где слушать |
| `LOG_LEVEL` | уровень логов |
| `RAW_DIR` | каталог сырых страниц парсера |
| `OUT_DIR` | каталог полных JSON после разбора |
| `DIRECTORY_DATA_DIR` | данные справочника, которые сервис отдаёт наружу |
| `INDEX_PATH` | файл сводного индекса |
| `LANDMARKS_PATH` | ориентиры из выгрузки 2ГИС |
| `PARSE_PAUSE`, `REQUEST_TIMEOUT` | вежливость и терпение при обходе сайта |
| `GEOCODER_PROVIDER` | подсказки DaData, Cleaner DaData или Nominatim |
| `DADATA_API_KEY` | ключ DaData; нужен для обоих режимов DaData |
| `DADATA_SECRET_KEY` | секрет DaData; нужен только для Cleaner |
| `GEOCODER_CONTACT` | реальный контакт для Nominatim: без него запросы отклоняются |
| `GEOCODER_TIMEOUT`, `GEOCODER_PAUSE` | ожидание и пауза между запросами к геокодеру |
| `NEAREST_RADIUS_KM`, `NEAREST_LIMIT` | радиус и число филиалов в подборе по умолчанию |

Секретов у сервиса два — ключи DaData. Они нужны и при заполнении координат
филиалов (`scripts/geocode_branches.py`), и в рантайме для `/api/geocode`,
если провайдер — DaData. Без геокодера ближайший филиал по месту не найдётся;
остальной справочник (города, цены, адреса по слагу) работает и без ключей.
При `GEOCODER_PROVIDER=nominatim` вместо ключей нужен `GEOCODER_CONTACT`.

## Тесты и линтер

```bash
uv sync
make lint
make test
make api_tests   # чёрный ящик по поднятому сервису
```

Проверено на текущем `main`: **223 теста зелёные, `ruff` чистый.**

Сеть тесты не трогают: подменяется только загрузка страницы, а разбор,
финализация и сборка работают на сохранённых фикстурах.

Отдельно покрыты два сценария, которые однажды ломали данные: частичный прогон
не должен уменьшать число городов, полный — не должен трогать города, собранные
руками. Плюс три проверки целостности по файлам: один адрес не встречается в
двух городах; филиал не дальше 50 км от центра своего города; две карточки не
имеют одинаковых координат. Без них бот может отправить клиента в чужой город
или дважды назвать один офис.

│   ├── directory_service/        справочник в памяти
│   │   ├── store.py              хранилище, загрузка, перечитывание
│   │   ├── lookup.py             поиск по слагу
│   │   ├── aliases.py            разговорные названия городов
│   │   ├── geo.py, geocoders/    координаты: DaData и Nominatim
│   │   ├── address.py            разбор адреса и срезание пояснений
│   │   ├── coords_integrity.py   защита от точек в чужом городе
│   │   └── data/                 41 JSON города — источник истины
│   └── parsing_service/          сбор и обогащение данных с сайта

Куда смотреть:

- поправить факт по городу или филиалу — JSON в
  `app/services/directory_service/data/`, затем `POST /api/reload`;
- добавить разговорный синоним города —
  `app/services/directory_service/aliases.py`;
- поменять разбор страницы сайта — `app/services/parsing_service/parse.py` и
  `sections.py`;
- поменять правила подбора ближайшего —
  `app/services/directory_service/lookup.py` и `geo.py`.

## Чего здесь нет намеренно

Базы данных, SQLAlchemy, Alembic, слоёв `models` и `crud`, Redis, очередей,
аутентификации. Источник истины — JSON-файлы на диске, и базы в проекте не
будет. Аутентификации нет, потому что сервис живёт во внутренней сети и наружу
не смотрит.

Из внутреннего стандарта осознанно взят `uv` вместо `requirements.txt`.

---

## Что осталось незаполненным

Не из-за кода — этих данных нет на источнике.

- **Расписание групп.** Ни в одном городе на сайте нет дат старта и остатка
  мест. Менеджеры в записанных разговорах оперируют ими постоянно — значит,
  живёт в CRM заказчика.
- **Районы и метро.** Почти везде пусто: сайт районы не пишет. Из-за этого бот
  не поймёт «я в Академическом» — филиал приходится подбирать перечислением
  адресов и ориентиров вслух.
- **Ориентиры** заполнены частично, из выгрузки 2ГИС.
- **Сроки обучения у трёх ручных городов** приходят пустыми: карточки категорий
  там в старом формате.
- **Цена — витринная.** Сайт даёт «от N рублей», независимые источники и
  записанные разговоры менеджеров дают суммы почти вдвое выше. Поэтому в ответе
  цена помечена как неподтверждённая и сопровождается оговоркой. Когда заказчик
  даст настоящий прайс, пометка снимется.

## Известные грабли

**Именованный том перекрывает данные из образа.** Данные городов едут внутри
образа, а именованный том заполняется из образа **только при создании**. Если
примонтировать каталог справочника, обновление образа не привезёт новые данные —
и никто об этом не узнает. В боевом стеке монтируется только каталог результатов
парсинга; `infra/docker-compose.yml` этого репозитория пока монтирует и каталог
справочника — использовать его на сервере нельзя.

**Пустой ответ выглядит как фантазия модели.** Если бот называет не те цены или
уходит от ответа, первым делом смотреть логи справочника, а не мозга.

**Частичный парсинг умеет стирать данные.** Поэтому `only` и проверка на
уменьшение числа городов — не украшение, а страховка. Не отключать.

**Три города собраны руками.** `include_done` по умолчанию выключен; включать
осознанно и понимая, что ручная работа будет перезаписана.

**В контейнере нет `curl`.** Healthcheck в боевом стеке написан на
`python -c "import urllib.request..."`. Проверки изнутри контейнера через `curl`
не сработают.

**`API_PORT`, `OUT_DIR`, `RAW_DIR` — общие имена.** В общий `.env` стека их
класть нельзя: `env_file` раздаст их всем контейнерам и перебьёт настройки
чужих образов. Место таких переменных — в `environment:` своего сервиса.

**После правки JSON руками нужен `POST /api/reload`.** Справочник читается в
память при старте; правка файла сама по себе ничего не меняет.
